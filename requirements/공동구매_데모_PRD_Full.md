## 1. 프로젝트 개요

### 1.1 목적
- **1차**: 마켓뱅 AI 워크샵에서 팀이 함께 빌드할 공동구매 v2 MVP 기획서
- **2차**: 빌드 결과물이 현재 운영 중인 공동구매 서비스에 이식 가능한 수준으로 검증

### 1.2 배경
현재 마켓뱅에서 공동구매를 운영 중이지만, 다음 한계가 있음:
- 정보 구조가 사용자에게 직관적이지 않음
- 참여 동기 부여 요소(소셜 증거)가 부재
- 어드민에서 상품 등록부터 마감까지의 라이프사이클이 분산되어 있음

이번 데모에서는 **단일 화면에서 풀 라이프사이클이 동작**하는 구조를 제시하여, 워크샵에서 검증 후 본 서비스에 적용한다.

### 1.3 성공 기준
- [ ] 어드민에서 상품 등록 → 유저 페이지에서 즉시 확인 가능
- [ ] 유저가 참여 → 실시간으로 참여 현황 반영
- [ ] 목표 수량 도달/미달에 따른 자동 확정/취소 동작
- [ ] 워크샵 종료 시점에 본 서비스 이식 의사결정 가능한 수준의 완성도

### 1.4 범위 (Scope)

**포함**
- 어드민: 공동구매 등록/수정/마감 처리
- 유저: 공구 탐색/참여/참여 취소
- 실시간 참여 현황 표시
- 목표 달성 시 확정, 미달 시 자동 취소

**제외 (Out of Scope)**
- 실제 결제 (PG 연동) — 데모 메시지로 대체
- 배송 트래킹 (상태 표시만)
- 알림 (이메일/SMS) — 화면 내 안내만
- 정식 회원가입 시스템 — 이메일만 입력

## 3. 핵심 사용자 스토리

### 3.1 어드민
- **AS-1**: 운영자로서 마켓뱅 상품 URL을 입력하면 상품 기본 정보가 자동 연동되어, 공구 등록 시간을 줄이고 싶다.
- **AS-2**: 운영자로서 공구 공급가, 목표 수량, 모집 기간을 설정하여 공구를 오픈하고 싶다.
- **AS-3**: 운영자로서 진행 중인 공구의 참여 현황을 실시간으로 확인하고 싶다.
- **AS-4**: 운영자로서 마감 시점에 목표 달성 여부에 따라 자동으로 확정/취소가 처리되길 원한다.

### 3.2 유저 (소매처)
- **US-1**: 소매처로서 현재 진행 중인 공구 상품과 조건(가격/수량/마감)을 한눈에 보고 싶다.
- **US-2**: 소매처로서 다른 소매처들이 얼마나 참여 중인지 보고 참여 결정을 내리고 싶다.
- **US-3**: 소매처로서 원하는 수량을 선택하여 참여 신청을 하고 싶다.
- **US-4**: 소매처로서 참여 후에도 마음이 바뀌면 취소할 수 있길 원한다.
- **US-5**: 소매처로서 공구가 확정되었는지/취소되었는지 명확히 알고 싶다.

## 4. 기능 명세

### 4.1 어드민 - 공구 등록

#### 4.1.1 상품 정보 연동
- **입력 방식**: 마켓뱅 상품 URL 입력 (`https://api.marketbang.kr/api/buyer/v1/goods/{상품번호}`)
- **자동 불러오기 필드**:
  - 상품명
  - 대표 이미지
  - 상품 설명
  - 수입사명
  - 정가 (참고용)
- **수동 입력/수정 필드**:
  - 공구 공급가 (필수, 정가와 별도)
  - 1인당 최소/최대 구매 수량

#### 4.1.2 공구 설정 필드
| 필드 | 타입 | 필수 | 비고 |
|---|---|---|---|
| 공구 제목 | text | O | 자동 생성 가능 (상품명 기반) |
| 모집 시작일시 | datetime | O | |
| 모집 종료일시 | datetime | O | |
| 목표 수량 | int | O | 최소 성사 수량 |
| 최대 모집 수량 | int | X | 미입력 시 무제한 |
| 공구 공급가 | int | O | |
| 1인 최소/최대 수량 | int | O | 기본값 1/제한없음 |
| 티어 가격 구조 | array | X | 옵션 (4.4 참고) |
| 배송 예정일 | date | X | 안내용 |

#### 4.1.3 공구 상태 머신
```
[모집중] → 목표 도달 → [확정] → [배송준비] → [완료]
         → 기간 종료 미달 → [자동취소]
         → 운영자 수동 종료 → [수동취소]
```

### 4.2 유저 페이지 - 공구 탐색/상세

#### 4.2.1 화면 구조 (1화면 = 1수입사 상품)
```
┌─────────────────────────────────┐
│  [상품 이미지]                   │
│  상품명                          │
│  수입사명                        │
├─────────────────────────────────┤
│  정가 ₩XX,XXX → 공구가 ₩XX,XXX  │
│  (할인율 표시)                   │
├─────────────────────────────────┤
│  [프로그레스 바: ████░░ 65%]    │
│  목표 100병 / 현재 65병          │
│  참여자 12명                     │
├─────────────────────────────────┤
│  ⏰ 마감까지 02일 14시간 23분    │
│  🔥 ○○와인바님 5분 전 참여      │
├─────────────────────────────────┤
│  [티어 가격 구조 - 옵션]         │
│  50병 달성: ₩45,000              │
│  100병 달성: ₩42,000 ← 현재      │
│  150병 달성: ₩40,000             │
├─────────────────────────────────┤
│  수량 선택: [- 6 +]              │
│  예상 결제 금액: ₩252,000        │
│  [참여하기]                      │
└─────────────────────────────────┘
```

#### 4.2.2 소셜 증거 요소
1. **실시간 참여 현황**: "○○님 외 N명 참여중" (참여 시점 기준)
2. **카운트다운 타이머**: "마감까지 02일 14시간 23분"
3. **목표 달성률 프로그레스 바**: 시각적 표시 + 백분율
4. **티어 가격 구조** (옵션): 달성 임박 시 가격 인하 단계 표시
5. **최근 참여자 알림**: "○○와인바님 5분 전 참여" (소매처명 일부 마스킹)

### 4.3 유저 페이지 - 참여 플로우

#### 4.3.1 참여 단계
1. **수량 선택**: -/+ 버튼으로 조정 (최소/최대 수량 검증)
2. **이메일 입력** (데모용): 비로그인 시 이메일만 입력
   - 본 서비스 이식 시: 마켓뱅 계정 로그인으로 대체
3. **참여 확인**: 수량 + 예상 결제 금액 표시
4. **참여 완료 처리**:
   - 데모: "결제는 데모용으로 처리되었습니다. 실제 서비스에서는 목표 수량 달성 시 결제가 진행됩니다." 메시지
   - 안내 문구: "공구 확정 시 ₩XXX,XXX 결제 예정 / 미달 시 결제되지 않습니다"
5. **참여 완료 화면**: 참여 내역 + 현재 참여 현황으로 이동

#### 4.3.2 참여 취소
- **취소 가능 시점**: 공구 마감 전까지 자유롭게 가능
- **취소 처리**: 참여 수량에서 해당 분량 차감, 참여자 수 -1
- **취소 사유** (옵션): 데모에서는 생략 가능

### 4.4 티어 가격 구조 (옵션 기능)

**도입 검토 포인트** (워크샵에서 결정)

#### 작동 방식
- 운영자가 등록 시 여러 단계의 (수량, 가격) 페어 입력
- 현재 달성 수량에 따라 적용 가격이 실시간 변경
- 참여 완료 후 더 낮은 티어 진입 시: 기존 참여자 가격 자동 조정

#### 예시
| 누적 수량 | 적용 가격 |
|---|---|
| 1~49병 | ₩48,000 |
| 50~99병 | ₩45,000 |
| 100~149병 | ₩42,000 |
| 150병+ | ₩40,000 |

#### 워크샵 검토 필요 사항
- 가격 인하 시점에 기존 참여자에게 어떻게 알릴 것인가?
- 차액 환불 방식 (실서비스 이식 시)
- UX 복잡도가 데모 시간 내 구현 가능한가?

### 4.5 마감 처리 로직

#### 4.5.1 자동 처리 (모집 종료 시점)
```
IF 현재수량 >= 목표수량:
    상태 = "확정"
    참여자 전원에게 확정 안내 (화면 표시)
    배송 준비 단계로 전환
ELSE:
    상태 = "자동취소"
    참여자 전원에게 미달 안내
    "결제되지 않았습니다" 메시지
```

#### 4.5.2 확정 후 단계
- 데모에서는 "배송 준비 중" 상태까지만 표시
- 운영자가 수동으로 "배송 완료" 처리 가능

## 5. 데이터 모델

### 5.1 GroupBuy (공구)
```
{
  id: uuid,
  title: string,
  marketbang_product_id: int,  // 마켓뱅 상품번호
  product_url: string,
  product_data: {              // 자동 연동된 정보
    name: string,
    image_url: string,
    description: string,
    importer_name: string,
    original_price: int
  },
  groupbuy_price: int,          // 공구 공급가
  target_quantity: int,
  max_quantity: int | null,
  min_per_user: int,
  max_per_user: int | null,
  tier_pricing: [               // 옵션
    { threshold: int, price: int }
  ],
  start_at: datetime,
  end_at: datetime,
  delivery_date: date | null,
  status: enum,                 // 모집중/확정/자동취소/수동취소/배송준비/완료
  created_at: datetime,
  updated_at: datetime
}
```

### 5.2 Participation (참여)
```
{
  id: uuid,
  groupbuy_id: uuid,
  user_email: string,           // 데모용 (이식 시 user_id)
  user_display_name: string,    // 소매처명 (예: ○○와인바)
  quantity: int,
  expected_amount: int,         // 예상 결제 금액 (현재 티어 기준)
  status: enum,                 // 참여중/취소/확정/취소완료
  created_at: datetime,
  cancelled_at: datetime | null
}
```

### 5.3 상태 머신 (GroupBuy.status)
- `RECRUITING` (모집중) — 초기 상태
- `CONFIRMED` (확정) — 목표 도달 + 마감
- `AUTO_CANCELLED` (자동취소) — 목표 미달 + 마감
- `MANUAL_CANCELLED` (수동취소) — 운영자 종료
- `PREPARING` (배송준비) — 확정 후
- `COMPLETED` (완료) — 배송 완료

## 6. 엣지케이스 & 정책

### 6.1 동시성
- **목표 수량 초과 참여**: 동시 참여로 max_quantity 초과 시 → 선착순 처리, 후순위는 "마감되었습니다" 안내
- **마감 직전 참여**: 종료일시 기준 서버 시각으로 판단

### 6.2 취소 처리
- **목표 도달 후 취소**: 취소 가능하나, 취소로 인해 목표 미달 시 → 공구 상태는 마감 시점에 재계산
- **마감 후 취소**: 불가 (확정 또는 취소 상태 진입)

### 6.3 티어 가격 적용
- 참여 시점의 티어 기준으로 expected_amount 기록
- 마감 시 최종 티어 기준으로 일괄 재계산 후 확정

### 6.4 데이터 검증
- 마켓뱅 상품 URL 형식 검증
- 존재하지 않는 상품번호 입력 시 에러 핸들링
- 모집 종료일시가 시작일시보다 빠른 경우 차단
- 목표 수량 ≤ 최대 모집 수량 검증

## 10. 부록

### 10.1 용어 정의
- **공구 (공동구매)**: 일정 수량 이상의 참여자가 모이면 개별 구매가보다 낮은 가격에 구매할 수 있는 형태의 거래
- **확정**: 목표 수량 도달로 공구가 성사된 상태
- **자동취소**: 목표 미달로 공구가 무산되어 결제가 진행되지 않는 상태
- **티어 가격**: 누적 참여 수량에 따라 단계적으로 적용되는 가격 구조

### 10.2 미결정 사항 (워크샵에서 결정)
- 티어 가격 구조 도입 여부
- 차액 환불 처리 방식 (티어 도입 시)
- 배송 처리 범위 (상태 표시 vs 실제 배송 트래킹)
